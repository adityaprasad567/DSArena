# Deployment guide

Three services: Neon (database), Render (API), Vercel (frontend). Deploy in that order --
each later step needs a URL from the one before it.

## 1. Database -- Neon

1. Create a project at [neon.tech](https://neon.tech).
2. Copy the connection string (starts `postgresql://...`, includes `?sslmode=require`).
3. Keep it handy for the backend's `DATABASE_URL`.

## 2. Backend -- Render

Using `backend/render.yaml` (Render's "Blueprint" deploy):

1. Push this repo to GitHub.
2. In Render, "New" -> "Blueprint", point it at the repo.
3. Render reads `render.yaml` and creates the `dsarena-api` web service.
4. Set the env vars flagged `sync: false` in the dashboard:
   - `DATABASE_URL` -- the Neon connection string from step 1
   - `CORS_ORIGINS` -- your Vercel URL once you have it (comma-separated if more than one, e.g. local + prod)
5. `JWT_SECRET_KEY` is auto-generated by Render (`generateValue: true`) -- no action needed.
6. Deploy. The build command runs `alembic upgrade head` automatically, so the schema
   is created on first deploy.
7. Confirm `https://<your-service>.onrender.com/health` returns `{"status": "ok"}`.

**Without the blueprint:** create a Python web service manually, set the build command
to `pip install -r requirements.txt && alembic upgrade head`, start command to
`uvicorn app.main:app --host 0.0.0.0 --port $PORT`, and set the same env vars by hand.

## 3. Frontend -- Vercel

1. Import the repo in Vercel, set the root directory to `frontend`.
2. Vercel auto-detects Vite; `vercel.json` already sets the build command and output dir.
3. Add an environment variable: `VITE_API_BASE_URL` = your Render URL from step 2.
4. Deploy.
5. Go back to Render and set `CORS_ORIGINS` to this Vercel URL (step 2.4) -- circular
   dependency between the two services is normal for a first deploy.

## 4. Verify

Visit the Vercel URL, register an account, open a visualizer, favorite it, and check
that it shows up on `/dashboard`. If favorites/history silently fail, it's almost always
a `CORS_ORIGINS` mismatch -- check the browser console for the blocked-origin error.

## Rollback

Both Render and Vercel keep previous deploys one click away from re-promoting --
no manual rollback tooling needed at this scale.
